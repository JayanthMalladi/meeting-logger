# 03 — Technical Specification

> Reference document: **what to build, and exactly how.** Each section lists
> the artifact, its file location, the data it carries, and the acceptance
> bar. Implement top-to-bottom; each layer is independently testable.

## 0. Stack & constraints
| Concern | Choice | Why |
|---|---|---|
| Framework | Next.js 16, App Router, `src/`, TypeScript | Scaffold already in place; API routes + pages in one deploy. |
| Styling | Tailwind v4 + shadcn-style minimal components | Fast, no design-system tax. |
| STT | **Groq `whisper-large-v3-turbo`** | Near-real-time, generous free tier, one key. |
| LLM (extraction) | **Groq `llama-3.3-70b-versatile`** (default) | Cheap, JSON-structured output, swappable to Claude/GPT via env. |
| Storage | **In-URL share (default)** + optional Supabase (free tier) | Zero-signup judge link; optional persistence for "saved" digests. |
| Slack | Incoming-webhook post | No app-approval flow; one-line value prop. |
| Deploy | Vercel | One-click, env vars map straight to the config below. |

**Single critical dependency:** `GROQ_API_KEY`. Everything degrades to a
clear message if it's absent.

## 1. Environment contract (`.env.local`, never committed)
```env
GROQ_API_KEY=            # required for transcribe + extract
STT_MODEL=whisper-large-v3-turbo
LLM_MODEL=llama-3.3-70b-versatile
# Optional persistence (share links work without it):
# SUPABASE_URL=
# SUPABASE_SERVICE_KEY=
```
Vercel: set the same five. The app must **render and explain gracefully** if
`GROQ_API_KEY` is missing (a banner: "Add GROQ_API_KEY to enable processing").

## 2. Data model
Types live in `src/lib/types.ts` (already committed). The canonical shapes:

```ts
Segment  = { start: number; end: number; text: string }
Decision = { text: string; ts?: string }
Action   = { text: string; owner?: string; due?: string; ts?: string }
Question = { text: string; ts?: string }
Extracted = {
  summary: string;          // 3 lines max
  decisions: Decision[];
  actions: Action[];        // owner + due where stated
  openQuestions: Question[];
  atRisk: string[];         // short phrases: "owner X overdue", "decision D blocked on Y"
}
Transcript = { text: string; segments: Segment[]; duration?: number }
MeetingMeta = { title?, attendees?, kind?, source?: "recorded"|"uploaded" }
```
**`ts` values are `"mm:ss"` strings** pointing into the transcript — the UI
uses them to scroll-to / highlight the moment.

## 3. API surface
Three route handlers under `src/app/api/` (route types generated by Next).

### 3.1 `POST /api/transcribe`
- **In:** multipart `audio` (blob, ≤ ~50 MB; accept webm/ogg/mp4/wav/m4a)
  + JSON fields `title?, attendees?, kind?`.
- **Out:** `Transcript` (`text` + `segments` + `duration`).
- **Impl:** stream the uploaded blob to Groq `audio/transcriptions`
  (`model=whisper-large-v3-turbo`, `language` auto, `response_format=verbose_json`
  for `segments` + timestamps). Proxy server-side so the key is never exposed.
- **Edge:** empty/too-long file → 400 with a human message; Groq 4xx/5xx →
  502 with the upstream status surfaced.

### 3.2 `POST /api/extract`
- **In:** `{ transcript: string, segments: Segment[], meta: MeetingMeta }`.
- **Out:** `Extracted` (validated against the JSON schema before return).
- **Impl:** build the prompt (§5), call Groq `chat/completions` with
  `response_format: { type: "json_object" }` (or strict JSON instruction),
  parse, **validate against a zod schema**, return the typed object. On
  validation failure, retry once with the error appended, else 422.

### 3.3 `POST /api/slack`
- **In:** `{ webhookUrl: string, extracted: Extracted, meta: MeetingMeta, shareUrl: string }`.
- **Out:** `{ ok: boolean }`.
- **Impl:** build a compact `blocks` payload (header + decisions + actions +
  open questions + at-risk + share link) and `fetch` the webhook.
- **Edge:** non-200 → `{ ok:false, error }` without throwing.

### 3.4 (optional, Day 2) `GET /api/results/[id]` + `POST /api/results`
Supabase-backed persistence for "Save this digest" so a saved link is stable
even if the URL-encode approach is too long. **Default share uses §4; this is
the fallback, not the primary path.**

## 4. Share links (zero-signup)
- After extraction, offer **Copy share link**.
- `shareUrl = origin + "/m/" + base64url(JSON.stringify({ meta, extracted, transcript }))`.
  - Transcript is included **truncated to a bounded size** (e.g. first ~6k
    chars) so the URL stays under Vercel's limits; the full board still
    renders from the encoded `meta`+`extracted`.
  - `route.ts` for `/m/[slug]` **decodes on the client** (a `"use client"`
    page that reads `useParams`) → renders the read-only board. No DB, no auth.
- "Save to Supabase" is the optional persistent upgrade.

## 5. LLM extraction prompt (the heart of the product)
System + user prompt produces **only** the `Extracted` JSON. Key rules:
- Classify every commitment into exactly one of:
  **decision** (agreed, closed), **action** (someone will do something),
  **open question** (unresolved).
- For actions, capture **owner** and **due date** *only when actually stated*;
  otherwise leave `undefined` (do **not** invent owners).
- Fill `atRisk` with ≤ 4 concrete flags (overdue items, blocked decisions,
  unowned actions).
- Every item carries a `ts` (mm:ss) of where it was said, chosen from the
  provided segment list.
- `summary` ≤ 3 lines, no fluff.
- Be **conservative**: if nothing is stated, return empty arrays — never pad.

We version this prompt in `src/lib/extractPrompt.ts` and keep a `promptVersion`
field so results are reproducible.

## 6. Client (pages & components)
```
src/
  app/
    page.tsx                 # "/" — record/upload + context + Process + results
    m/[slug]/page.tsx        # share view (client-decoded, read-only board)
    layout.tsx
    globals.css
    api/ transcribe/ extract/ slack/   (route.ts)
  components/
    Recorder.tsx             # MediaRecorder: record/stop, live timer, blob out
    Uploader.tsx             # drag-drop / file input → blob
    ContextForm.tsx          # title, attendees, kind (all optional)
    Board.tsx                # summary + decisions + actions table + open q + at-risk
    TranscriptPanel.tsx      # segments with click-to-highlight; "read back" via speechSynthesis
    ShareCard.tsx            # copy link + Save + Post-to-Slack (webhook)
  lib/
    types.ts                 # (done)
    extractPrompt.ts
    groq.ts                  # thin fetch wrapper for transcribe + chat
    share.ts                 # encode/decode + size guards
    schema.ts                # zod schema for Extracted
```
**Recorder details:** `MediaRecorder` with `audio/webm` (Chrome) / `audio/mp4`
(Safari) fallback; stop → `Blob` → same path as upload. No third-party
recorder lib. A "what you just said" quick-transcript check (reuse
`/api/transcribe`) before the user commits to extraction, so bad audio is
caught early.

**Board details:** action table with owner/due columns; `atRisk` renders as
amber flags; each row links to its `ts` → TranscriptPanel scrolls + flashes
that segment.

## 7. Security & privacy
- API keys only in server env; browser never sees `GROQ_API_KEY`.
- Audio: processed in-request; **not stored** by default. If Supabase is
  enabled, we store transcript + extracted result, not raw audio.
- Share links are unguessable (opaque slug) but intentionally **public
  read-only** — note in UI: "Anyone with the link can read this digest."
- Slack webhook URL entered by the user is sent only to Slack, stored in the
  page state (not persisted unless Save is used).
- CORS: not needed (same-origin API + direct Slack fetch from server).

## 9. Test / verification gates (no test framework; manual + typecheck)
1. `npm run build` passes (TS + Next route types).
2. Record a 30s standup → get a board with ≥1 decision and ≥1 action, each
   with a `ts` that highlights the right segment.
3. Copy share link → open in incognito (no login) → board renders.
4. Paste a throwaway Slack webhook → digest posts with the link.
5. Missing `GROQ_API_KEY` → app still loads with a clear banner, no crash.
6. 2-min demo recorded against gates 2–3.
