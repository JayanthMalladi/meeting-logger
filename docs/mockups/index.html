NoHands Log: three UI directions

Mockups for the Wispr Flow hackathon build. Each option shows the same four moments of the demo loop: Dictate (Wispr Flow recap is the hero input), Generating (transcribe → extract, with live states), Board (decisions, actions, questions, risks, each linked to its source sentence) and Share (the zero-login link view). Same sample recap in all three so they compare fairly.

A · Ledger B · Voice Stage C · Split Studio Recommendation

A · Ledger

The spec's design direction, done carefully. One calm column (max 768px), zinc neutrals, emerald / sky / amber accents. The board reads like a minutes document. Generation shows step labels with elapsed seconds, then items fade in section by section.

Why it works

  • Lowest build risk: matches SPEC §6 and TASKS-B as written
  • Great at 375px and in dark mode
  • Reads well in a 1:45 screen recording

Trade-offs

  • Least memorable visually
  • Wispr Flow is a hint, not the show
  • Transcript sits below the board, so the "click → sentence lights up" moment needs a scroll

B · Voice Stage

Dark, cinematic, built for the demo video. The Wispr Flow moment is the hero: a glowing voice orb, live text appearing under it, then the board assembles as a three-column kanban while the model's reasoning streams in.

Why it works

  • Strongest "No Hands" story for judges
  • Generation is visible and exciting, not a spinner
  • Kanban (Decided / To do / Open) scans fast

Trade-offs

  • Off-spec: needs new styling, more Track B time
  • Three columns collapse to tabs at 375px
  • Orb animation is decorative; Wispr types into a focused field, so the live box must be a real textarea

C · Split Studio

A working tool: transcript on the left, board on the right, always both visible. Every item carries its evidence, and clicking one lights up the sentence (or seeks the audio) without scrolling. Warm paper tones with amber as the link color.

Why it works

  • Best showcase of the "every item linked to its source" feature
  • Click → highlight / seek happens in one view, ideal for the demo beat at 0:50
  • Feels like a product people would use daily

Trade-offs

  • Breaks the spec's single 768px column; stacks on mobile
  • Denser, less dramatic on first impression
  • Needs layout work in page.tsx, not just restyling

Recommendation: A as the base, with two pieces borrowed from B and C

Ship Option A (Ledger) because it is what SPEC §6 and TASKS-B already describe, so Track B can build it tonight without re-planning, and it holds up at 375px and in dark mode (both on the acceptance checklist).

Borrow from B: the generating state. Replace a plain spinner with step labels plus items fading into their sections as they arrive, and a "Listening via Wispr Flow" badge on the textarea while text is being typed. It's CSS-only and makes the demo feel alive.

Borrow from C: on screens ≥1024px, put the transcript panel beside the board (sticky) so the "click an action → sentence lights up / audio seeks" beat happens without scrolling. Below 1024px it stays the single column from A.

Pick B if you want maximum judge wow and have an hour of spare UI time. Pick C if you plan to keep building this after the hackathon as a daily tool.
